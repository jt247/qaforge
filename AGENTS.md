# Shared agent operating instructions
Read README.md, standards/testing-standard.md, standards/security-testing-policy.md, standards/agent-collaboration.md, and the product QA guide before testing. Codex also reads CODEX.md; Claude Code also reads CLAUDE.md.
The filesystem is durable context. Never infer completed tests from previous chat prose. Never report a pass without execution and evidence. Never invent product requirements, accounts, URLs, integrations, or backend coverage.
Use tooling/lab.py for configuration checks, run creation, results, and reports. Configuration records who authorized the assessment and how, and it expires after fourteen days. Claim a run with the CLI before browser testing; release it at handoff. Use separate run IDs and test accounts for parallel agents. Do not edit another agent's original evidence or results. Review through peer-review.md.
The two agents work inside the ECC engineering layer (github.com/affaan-m/ECC, MIT). Plan before changing lab tooling, run a fresh-context code review of every tooling change, and run a secret scan against the repository before enabling a new product target. README.md lists the exact ECC surfaces used.
Only target the explicitly enabled environment in product.json. Production defaults to read-only. Creating accounts, sending messages, changing records, or making payments needs that action allowed in the saved environment scope. Do not follow unexpected redirects outside approved hosts.
Keep credentials, OTPs, session states, test phone numbers, and unredacted personal data out of tracked files and reports. Evidence directories are ignored by Git. Redact before sharing.
Record blocked and not-run checks honestly. Freeze completed runs; fixes require a new linked run. Do not claim release readiness from reachability checks alone. No automatic deployment, notification to third parties, or risk acceptance.
